Even better: test each NLB IP independently

Suppose:

dig +short $LB

returns:

10.64.x.10
10.64.y.20
10.64.z.30

Test each one while preserving the correct hostname/SNI:

for IP in $(dig +short $LB); do
  echo "===== Testing $IP ====="

  for i in {1..10}; do
    curl -kIs \
      --connect-timeout 5 \
      --resolve "${CONSOLE}:443:${IP}" \
      https://${CONSOLE}/ \
      | head -1

    sleep 2
  done
done

Check the NLB target health in AWS

If your bastion has AWS CLI permissions, this is the next thing I'd inspect.

Find the NLB:

aws elbv2 describe-load-balancers \
  --region us-east-1 \
  --query "LoadBalancers[?DNSName=='${LB}'].[LoadBalancerArn,DNSName,State.Code]" \
  --output table

Then get the target groups using the returned LB ARN:

aws elbv2 describe-target-groups \
  --load-balancer-arn <LOAD_BALANCER_ARN> \
  --region us-east-1

Then:

aws elbv2 describe-target-health \
  --target-group-arn <TARGET_GROUP_ARN> \
  --region us-east-1 \
  --output table

We want every relevant target:

healthy

and not:

unhealthy
initial
draining
unavailable

If one target is intermittently unhealthy, that would fit your symptoms extremely well.
