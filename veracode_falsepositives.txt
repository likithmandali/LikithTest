Below 1, 2, 3 - have been communicated to Das, Debasish (Contractor) and Mazhar, Umair (Contractor) - email on 8/13/2025, with the following note for each (See Reference #1):

KSV118 – Default security context configured: In a ROSA (Red Hat OpenShift Service on AWS) environment, this is not an applicable security risk
ROSA automatically assigns a random non-root UID and GID at runtime to containers, regardless of the securityContext in the YAML. Red Hat’s guidance explicitly recommends not setting a fixed UID/GID in deployment manifests, as the platform enforces the correct values automatically. The current Kustomize code’s lack of explicit settings does not weaken security in ROSA. The ROSA infrastructure and its enforced SCCs override any less-restrictive defaults in application code. Therefore, this is false alarms from a scanning perspective and are already mitigated by platform controls in PATH NC infrastructure.  (Ref: Chapter 12. Managing security context constraints | Authentication and authorization | Red Hat OpenShift Service on AWS | 4 | Red Hat Documentation )

KSV014 – Root file system is not read-only: In a ROSA (Red Hat OpenShift Service on AWS) environment, this is not an applicable security risk
While Kustomize does not set securityContext.readOnlyRootFilesystem to true, ROSA’s enforced pod security and restricted SCCs (Security Context Constraints) control filesystem access at the platform level. The container’s effective permissions are already limited by the SCC, and setting this flag manually is optional, not mandatory, in ROSA-managed workloads. The ROSA infrastructure and its enforced SCCs override any less-restrictive defaults in application code. Therefore, this is false alarms from a scanning perspective and are already mitigated by platform controls in PATH NC infrastructure. (Ref: Chapter 12. Managing security context constraints | Authentication and authorization | Red Hat OpenShift Service on AWS | 4 | Red Hat Documentation ) 

DS-002 - Image user should not be 'root': Root privilege is a FALSE alarm as ROSA auto-generates UID & GID, which the Kustomize should not set manually as best practice. This is addressed under PATH NC infrastructure already. (Ref: A Guide to OpenShift and UIDs)
